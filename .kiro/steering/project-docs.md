# Project Documentation Standard

For every project, always create and maintain Markdown (`.md`) documentation.

## Rules

- Every project MUST have a `README.md` at its root describing what it is, how
  to set it up, run it, and deploy it.
- When a notable feature is added or a significant change is made, update the
  relevant `.md` docs so they stay accurate.
- Prefer keeping documentation close to the code it describes. For larger
  projects, use a `docs/` folder with focused Markdown files.
- Documentation should be written in clear, plain language and kept up to date
  as the project evolves.

## Minimum README contents

1. Project name and a one-line description
2. Features overview
3. Tech stack
4. Setup / installation steps
5. How to run locally
6. How to build and deploy
7. Environment variables (if any)
